  CHANGELOG - GAMGUI

08-07-2026  v1.11 FIX (important): Drive transfers now handle SUSPENDED and
                  ARCHIVED old accounts. GAM cannot transfer Drive files out
                  of a disabled account, so both "Transfer My Drive to another
                  user" and the "Move ... into a NEW Shared Drive" workflow
                  now detect the old account's state, temporarily enable it
                  (unsuspend/unarchive), do the transfer/move, then RESTORE
                  the exact original state - active stays active, suspended is
                  re-suspended, archived is re-archived. Also fixes a latent
                  bug where the Shared Drive workflow always re-suspended
                  (would wrongly suspend an account that started active).
                  Restore runs even if you hit Stop, so an account is never
                  left enabled. (Mirrors the enable-transfer-disable logic
                  from the original offboarding batch script.)
08-07-2026  v1.10 NEW: Drive > "Move a user's Drive INTO a NEW Shared Drive"
                  workflow - ported from the Move-UserDrive-to-SharedDrive
                  batch: unsuspend old user, create a Shared Drive, move their
                  My Drive into it, make the new user a manager, remove the
                  temporary admin/old-user access, re-suspend. Reads the new
                  Shared Drive id from the create output.
                  IMPROVED: "Transfer My Drive to another user" now documents
                  that GAM already lands the files in a subfolder named
                  "<old user> old files" (not the root) and adds an optional
                  folder-name field (targetuserfoldername; tags #user# /
                  #username#). Clarifies the benign "Permission ID ... Does
                  not exist" (rc 56) that can appear during a transfer - it is
                  a stale-permission cleanup notice, not a transfer failure.
08-06-2026  v1.9  FIX (startup crash): app failed to launch with
                  "FileNotFoundError: Tcl data directory _tcl_data not
                  found" (reported by Gabe, seen repeatedly). Root cause:
                  Python 3.14 ships Tcl/Tk 9, which stores its script library
                  INSIDE the DLL as a zip filesystem (//zipfs:/...);
                  PyInstaller 6.21 bundles the Tcl/Tk DLLs but NOT that
                  library, so _tcl_data was absent and tkinter could not
                  initialize - every launch crashed. (Earlier "intermittent"
                  successes were the windowed crash DIALOG keeping the
                  process alive, fooling the alive-check.) Fix: (1) switched
                  from one-file to ONE-FOLDER packaging (also removes the
                  fragile extract-to-%TEMP% behavior), and (2) added
                  extract_tcl.py to pull the Tcl/Tk libraries out of the
                  zipfs and bundle them via --add-data as _tcl_data/_tk_data.
                  Verified: 7/7 clean launches. Build-EXE.bat updated to v2.0
                  (runs the extract step). New launch path:
                  C:\GAM7\GAMGUI\GAMGUI.exe (or the "Launch GAMGUI" shortcut).
08-06-2026  v1.8  HARDEN: _poll_output (the UI output loop) could die and/or
                  deadlock. If the DELETE-confirmation dialog ever threw, its
                  event was never set (worker thread hung forever, app looked
                  frozen) AND the exception escaped the poll method, skipping
                  the reschedule and killing all further output + printing a
                  traceback. Now: the confirm branch always releases its event
                  (finally), any poll-loop error is caught/logged, and the
                  100ms reschedule always runs (finally). Investigated after
                  Gabe reported a Python error on screen; no traceback was
                  found in the app logs (most likely an open instance being
                  force-killed during a rebuild), but this closes the real
                  latent crash/freeze path that v1.7 first made reachable.
07-23-2026  v1.7  FIX: "Full incident-response workflow" aborted mid-run
                  with "[workflow stopped: discovery failed or canceled]"
                  even though nothing was canceled. Cause: a domain-wide
                  "all users print messages" returns a NONZERO exit code
                  whenever ANY mailbox fails the query, and on a large
                  domain some always do (suspended/unlicensed/unprovisioned
                  mailboxes). The Phase 1 check treated any nonzero exit as
                  fatal. Reproduced: a 2-user search with one failing user
                  returned rc 50 yet still wrote the results CSV. Fix:
                  Phase 1 now aborts only on a real user cancel or a missing
                  results file; a nonzero exit with results present is
                  reported as a normal "some mailboxes skipped" note and the
                  workflow continues. Found by Gabe in live use.
07-23-2026  v1.6  DIAGNOSED (not a GAMGUI bug): an "&" subject returning 0
                  matches is GMAIL search behavior, not truncation - a
                  read-only probe showed gam receives the full query with
                  the & intact. FIX: the incident workflow now groups
                  subject words as subject:(...) instead of quoting the
                  whole phrase, which Gmail matches far more reliably and
                  tolerates punctuation like &. (Discovery stays broad on
                  purpose; deletion is still by exact Message-ID.)
                  NEW (Security): "Mailbox takeover audit (one user)" -
                  one-click read-only sweep of Gmail filters, forwarding
                  addresses, send-as, and delegates (the footholds an
                  attacker leaves after phishing an account). Plus "Show
                  mailbox rules (Gmail filters)". Note: Gmail's API has no
                  filter creation timestamp, so "freshly created" cannot
                  be isolated - the audit lists all current rules to spot
                  what does not belong. All four show-commands verified
                  against real gam (rc=0).
                  NEW: HOW-TO-GUIDE.txt - full plain-English guide for
                  non-technical coworkers who have never used GAM or a CLI.
07-23-2026  v1.5  NEW: the incident-response workflow is now BUILT IN
                  (requested by Gabe - previous version launched a batch
                  script that only exists on his machine). Four phases:
                  domain-wide discovery to an evidence CSV, typed-DELETE
                  confirmation showing hit counts, deletion by exact
                  Message-ID (query fallback), and Gmail/Drive audit
                  report pulls. Evidence lands in Logs\Incident_<stamp>\
                  with a Summary.txt. Stop cancels between phases and
                  kills the current step. CSV column names verified
                  against real gam output (Message-ID). The external
                  script launcher task was removed. Not ported from the
                  batch original: attachment hash/Drive-presence
                  correlation (see README Known Limitations).
07-23-2026  v1.4  FIX: an "&" (or other shell-special character) in a
                  subject/query silently cut the command in half - cmd.exe
                  does not understand the \" escapes, saw the quote as
                  closed, and treated & as a command separator. Found by
                  Gabe: delete ran with a truncated query AND without its
                  doit/max arguments. Commands now run WITHOUT a shell:
                  the form builds a real argument list passed straight to
                  gam, so & | > < ^ and quotes in values are plain text.
                  Edited previews / Custom commands are parsed with
                  Windows-rule splitting (win_split). Side effect: shell
                  pipes and > redirection are no longer available in
                  Custom mode - use GAM's own redirect/todrive (noted in
                  the UI and README).
                  IMPROVED: every query/ID/OU prompt now shows an inline
                  example (e.g. Gmail query, OU paths, SKU, Course ID) for
                  operators who do not know GAM syntax.
07-23-2026  v1.3  FIX: message trash/delete tasks put "doit" before
                  "max_to_trash/max_to_delete"; GAM requires doit at the
                  end and errored asking for it. All four affected
                  templates corrected (order now matches the proven
                  EmailCleanup batch script). Found by Gabe in live
                  testing of a single-user delete.
07-23-2026  v1.2  NEW: "Email Cleanup" category (requested by Gabe):
                  domain-wide message search preview, domain-wide trash/
                  delete with max-per-mailbox seatbelt, single-mailbox
                  delete, and a launcher for the incident-response
                  workflow (GAM7-Workspace-Email-Cleanup.bat) which opens
                  in its own console because it is interactive.
                  FIX: command builder stripped embedded double quotes,
                  breaking Gmail queries like subject:"Gift Card". Inner
                  quotes are now escaped as \" per GAM convention.
                  Now 75 gam tasks + 1 external workflow in 14 categories.
07-23-2026  v1.1  FIX: Stop button did not actually stop the running gam
                  command. shell=True wraps gam in cmd.exe and proc.kill()
                  only killed the wrapper, orphaning gam.exe. Stop now
                  kills the full process tree (taskkill /T /F on Windows,
                  process-group SIGKILL on macOS/Linux) and reports
                  honestly if the stop fails. Reported by Gabe; repro and
                  fix verified with a synthetic child-process test.
                  (A Ctrl+C-style graceful interrupt is not possible from
                  a windowed app - console control events need a console.)
07-23-2026  v1.0  Initial release. 71 tasks / 13 categories + custom mode.
                  Threaded runner, session logs, destructive confirmations,
                  gam auto-detect, PyInstaller build script.
